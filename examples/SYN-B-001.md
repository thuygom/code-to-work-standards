# SYN-B-001 — 고객 사실과 제품 적합성 가설을 구분하는 사례

**기업·제품·자료가 모두 가상인 합성 예시이며 실행·현업 검토 전입니다.** 실제 제품의 기능이나 실제 영업 성과를 주장하지 않습니다. 외부 URL과 실제 고객 자료를 사용하지 않습니다.

| 항목 | 값 |
|---|---|
| 예시 ID | `SYN-B-001` |
| 사례 ID | `CASE-B-001` — 합성 예시용으로 사용합니다. |
| 원천·사용 구분 | 합성 / 예시 전용 |
| 출력 유형 | B2 제품 연결·영업 판단 |
| 기대 결과 상태 | 초안, 현업 승인 전 |
| 실행 상태 | 미실행 |
| 관련 단계 | `B09`, `B10`, `B11`, `B12`, `B13` |
| 관련 요구 | `PRD-B-07`, `PRD-B-08`, `PRD-B-09` |

## 가상 요청

가상기업 A의 공장 증설 소식과 자사제품 P의 기능 자료를 보고, 확인한 사실과 영업 검토 가설을 구분해 다음 질문을 정리해 주세요. 제품 도입이나 고객 접촉을 실행하는 요청은 아닙니다.

## 가상 자료

| 자료 위치 | 제공된 내용 |
|---|---|
| `SRC-SYN-B-001:A1` | 가상기업 A는 제2공장 가동을 준비하고 있다고 발표했습니다. |
| `SRC-SYN-B-001:A2` | 발표에는 현재 점검 기록 방식, 정보 시스템, 예산, 구매 의사와 도입 시점이 없습니다. |
| `SRC-SYN-B-001:P1` | 제품 P v1.0의 현재 기능은 설비 점검 기록 입력과 이력 조회입니다. |
| `SRC-SYN-B-001:P2` | 외부 생산 시스템 연계는 별도 검토가 필요합니다. 예지보전은 검토 중인 방향이며 현재 제공 기능이 아닙니다. |

## 기대 판단

| 구분 | 기대 결과 | 근거 또는 확인할 내용 |
|---|---|---|
| 확인 사실 | A가 제2공장 가동을 준비한다고 발표했습니다. | A1 |
| 니즈 가설 | 공장 확대에 따라 점검 기록을 모으는 업무가 늘어날 가능성을 검토할 수 있습니다. | A1에 기초한 가설이며 고객 확인 전입니다. |
| 다른 가능한 설명 | 이미 기존 시스템에서 점검 기록을 충분히 관리할 수도 있습니다. | 확인 질문을 위한 대안 가설이며 사실로 단정하지 않습니다. |
| 현재 제품 기능 | P v1.0은 점검 기록 입력·이력 조회를 지원한다는 가상 자료가 있습니다. | P1 |
| 조건부 적합성 | 기록 입력·조회가 실제 문제라면 검토 후보가 될 수 있습니다. 기존 방식과 필요 연계를 먼저 확인해야 합니다. | A2·P1·P2 |
| 제외할 주장 | 현재 예지보전 제공, 확정 예산, 도입 예정, 구매 의사가 높다는 확정은 근거가 없습니다. | A2·P2 |

## 다음 확인 질문

1. 현재 점검 기록은 어떤 방식으로 입력·조회하며 무엇이 불편합니까?
2. 기존 공장과 새 공장의 기록을 함께 볼 필요가 있습니까?
3. 필요한 연계 대상과 데이터 형식은 무엇입니까?
4. 실제 문제, 검토 담당자, 우선순위와 판단 시점을 고객이 확인했습니까?
5. 제품 담당자가 현재 기능과 추가 연계의 제공 범위를 확인했습니까?

## 수용과 반려

수용 후보는 고객 사실, 아직 확인하지 않은 니즈, 현재 제품 기능, 조건부 연결과 다음 질문을 구분합니다. 부적합 조건과 반대 근거를 점검하되 발견하지 못한 반대 사실을 만들지 않습니다.

다음 결과는 반려합니다.

- “A는 예지보전 시스템 도입을 계획하고 있습니다.”
- “P v1.0이 예지보전과 기존 생산 시스템의 즉시 연계를 제공합니다.”
- “공장 증설이므로 P를 구매할 가능성이 높고 예산도 확보되어 있습니다.”
- 자료에 없는 고객 답변·제품 성능 수치·외부 출처를 생성합니다.

## 연결과 후속 검증

`B09–B13 → PRD-B-07·08·09 → CASE-B-001 → 실제 실행 시 RUN-B-… → 결정 시 DEC-B-…`

현재 실행·검토 수치와 채택 결정은 없습니다. 실제 고객·제품 자료를 사용한 검증은 비공개 원문과 승인된 공개 기록을 분리하고, 별도 실제 사례의 수용 기준을 먼저 확정해야 합니다.
