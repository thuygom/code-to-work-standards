# 일정 SOP — 제안·조율·확정을 구분하는 기록

문서 기반 제안 · 현업 검증 전. 아래 고객·담당자와 날짜 사례는 합성입니다.

## 목적

미래 접촉·이벤트와 조율 상태를 잃지 않으면서, 마감이 있는 할 일을 일정으로 잘못 바꾸지 않습니다. 초안 작성은 실제 캘린더 등록이나 상대방의 수락을 의미하지 않습니다.

| 단계 | 수행 | 완료 조건 | 예외·재개 |
|---|---|---|---|
| S01 기준 확보 | 원문 작성 시각·시간대·참석자 역할을 확인 | 상대 날짜 해석 근거 확보 | 전사 타임코드를 실제 약속 시각으로 사용하지 않음 |
| S02 이벤트 식별 | 미팅·통화·방문과 조율 행동을 구분 | 대상·목적·접촉 의도 기록 | 단순 결과물 마감은 할 일로 연결 |
| S03 상태 기록 | 제안·조율 중·수락·취소를 분리 | 근거 발화와 상태 연결 | “가능할까요?”만으로 확정하지 않음 |
| S04 시간 정리 | 확실한 날짜·시간과 미정 부분을 분리 | 원문 표현과 정규화 값을 함께 보존 | 정보가 없으면 임의 시간 생성 금지 |
| S05 중복·준비 연결 | 같은 이벤트를 합치고 독립 준비 업무 유지 | 대상·시점·목적 기준으로 비교 | 같은 제목의 다른 주간 일정은 별도 유지 |
| S06 등록·인계 | 승인된 범위만 대상 캘린더에 등록 | 실제 저장 결과·식별자 확인 | 응답 유실은 기존 결과 조회 후 재시도 |
| S07 변경·완료 | 변경·취소 이유와 영향받는 업무를 기록 | 참석자 인지·후속 행동 확인 | 일정 취소가 준비 업무 삭제로 자동 이어지지 않음 |

## 기록 양식

이벤트 ID / 목적 / 대상 / 원문 근거 / 기준시각·시간대 / 날짜·시각·미정 부분 / 제안·수락 상태 / 관련 준비 업무 / 저장 결과 / 변경 이유.

## 합성 예시

“고객사 A와 다음 주 통화 시간을 잡아 주세요. 그 전에 제안서를 보내 주세요.”는 통화 조율 일정 1건과 제안서 전달 업무 1건입니다. 통화 시간이 미정이면 미정 상태로 유지합니다. 원문 작성일이 없으면 “다음 주”의 달력 날짜를 확정하지 않습니다.

## 출처와 한계

IScribe의 할 일·일정 구분 명세와 writingAgent의 행동 분류·시간 맥락 규칙을 공개용으로 재구성했습니다. 관계 유지가 목적인 연락을 일정으로 보는 것은 이 기여의 분류 관점이며 모든 조직에 강제하는 정의가 아닙니다. 실제 일정 연동이나 인물 매칭 정확도는 별도 검증해야 합니다.
