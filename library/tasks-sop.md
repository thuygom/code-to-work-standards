# 할 일 SOP — 행동과 결과물을 빠뜨리지 않는 인계

문서·코드에서 도출한 제안입니다. 아래 예시는 합성·미실행이며 현업 관찰 결과가 아닙니다.

## 목적과 범위

회의·메일·메모에 나온 실행 업무를 담당자가 수행하고 결과를 확인할 수 있는 기록으로 바꿉니다. 접촉·이벤트 자체와 그 준비 업무를 구분합니다. 팀의 승인 정책과 사용하는 도구의 기능은 별도 확인합니다.

| 단계 | 입력 → 수행 | 책임 | 완료·예외 |
|---|---|---|---|
| T01 맥락 확보 | 공개 가능한 원문, 기준일, 시간대, 참여자의 역할을 확인 | 작성자 | 누락 정보는 추정하지 않고 확인 대기 |
| T02 행동 분리 | 독립적으로 수행할 수 있는 행동과 결과물을 나눔 | 작성자·분석 도구 | 한 문장에 여러 행동이 있어도 하나로 합치지 않음 |
| T03 종류 판정 | 접촉·행사는 일정, 결과물·상태 변경은 할 일로 구분 | 업무 담당 | 마감일이 있다는 이유만으로 일정으로 바꾸지 않음 |
| T04 소유·수락 확인 | 요청자, 실행자, 요청과 수락 상태를 따로 기록 | 실제 수행자 | 언급된 사람이 곧 담당자라고 단정하지 않음 |
| T05 완료 기준 작성 | 할 일, 대상, 산출물, 기한 또는 다음 확인 조건, 근거를 기록 | 수행자·검토자 | 불명확한 기한은 미정으로 유지 |
| T06 중복·의존 확인 | 대상·행동·시점·목적을 비교하고 준비 업무 연결 | 작성자 | 제목 유사도만으로 삭제하지 않음 |
| T07 확정·저장 | 수락된 범위와 기준 버전으로 저장 | 업무 소유자·시스템 | 응답 유실이면 기존 결과를 조회, 무조건 재등록 금지 |
| T08 실행·재개 | 결과물 확인 후 완료, 실패·대기 사유와 다음 확인을 기록 | 수행자·검토자 | 후보 생성이나 전달만으로 완료 처리하지 않음 |

## 바로 쓸 기록 양식

- 업무 ID / 원문 근거:
- 요청자 / 수행자 / 수락 상태:
- 행동 / 대상 / 산출물:
- 기한 또는 다음 확인 조건:
- 완료를 판단할 증거:
- 관련 일정·선행 업무:
- 현재 상태 / 변경 이유 / 기준 버전:

## 합성 사례

고객사 A와 금요일에 만날 예정이며 견적서를 보내고 데모 계정을 준비해야 합니다. 기록은 일정 1건과 준비 업무 2건입니다. 미팅이 취소되어도 준비 업무를 자동 삭제하지 않고 필요 여부를 담당자가 판단합니다. 담당자 A가 요청만 받은 경우에는 수락 미확인으로 남깁니다.

## 확인 방법

같은 통화를 두 번 언급한 사례, 서로 다른 고객에게 같은 자료를 보내는 사례, 시간이 있는 자료 작성, 기한 없는 독립 업무를 함께 검토합니다. 분류 정확도·누락·중복·실행 시간은 아직 측정하지 않았습니다.

## 출처와 가공 범위

IScribe의 할 일·일정 구분 명세와 writingAgent의 행동 분류 규칙을 공개용으로 재구성했습니다. 기업·인물은 고객사 A·담당자 A로 바꾸었고 실제 대화·계정·연락처·운영 주소는 포함하지 않았습니다. 내부 API 한도와 제품별 수치를 공통 업무 기준으로 옮기지 않았습니다. 소스 확인 버전은 [초기 자료 출처 기록](README.md)에 있습니다.
