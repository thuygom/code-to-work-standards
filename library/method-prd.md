# PRD 시작 양식 — 무엇이 되면 충족한 것인가

## 참고 원칙

NASA Systems Engineering Handbook Appendix C는 명확하고 하나의 의미를 가진 요구, 근거와 가정, 고유 식별자, 추적성과 검증 가능성을 점검하도록 안내합니다. 제품이 해야 할 일과 작업자의 업무 지시를 구분합니다. 항공우주 지침을 일반 제품 요구 작성에 제한적으로 참고했습니다.

## 이 프로젝트의 작성 양식

- 문제 / 사용자 / 사용 상황:
- 이번 범위 / 제외할 범위:
- 요구 ID / 필요한 동작 / 이유:
- 연결된 SOP 단계와 MoW 인계:
- 정상 입력 → 기대 결과:
- 경계·실패 입력 → 기대 처리:
- 수용 확인 방법 / 근거 위치:
- 미정 항목 / 확인 담당 / 해결 조건:

## 합성 개선 예시

“쉽게 수정할 수 있어야 한다”를 “사용자가 선택한 항목의 제목을 바꾸면, 선택하지 않은 항목의 식별자와 확정 상태가 유지된다”로 구체화합니다. 성능 목표가 필요하면 조직에서 측정 조건과 임계값을 합의합니다. 근거 없는 수치를 채워 넣지 않습니다.

## 출처와 이용 범위

[NASA, Appendix C: How to Write a Good Requirement](https://www.nasa.gov/reference/appendix-c-how-to-write-a-good-requirement/). 2026-10-30 확인. 짧은 요약과 자체 작성 양식입니다. 원문 전체·로고·이미지를 복제하지 않았고 NASA가 이 자료를 인증했다는 의미가 아닙니다. PRD 자체의 범위는 제품별로 정해야 합니다.
