# 할 일 PRD — 요청에서 실행 가능한 업무까지

상태: 요구사항 제안 · 현업 검증 전. 기능 구현이나 성능 검증 완료 목록이 아닙니다.

## 문제와 사용자

팀원은 누가 무엇을 수락했는지, 언제 어떤 결과를 내야 하는지 알아야 합니다. 작성 도구가 요청을 확정 업무로 바꾸거나 서로 다른 준비 업무를 지우면 인계가 틀어집니다.

| 요구 ID | 필요한 동작 | 정상 수용 조건 | 경계·실패 수용 조건 |
|---|---|---|---|
| PRD-T-01 | 독립 행동을 분리 | 미팅·견적 전달·계정 준비를 각각 보존 | 한 문장이라는 이유로 합치지 않음 |
| PRD-T-02 | 요청자·실행자·수락 상태 구분 | 수락 근거가 있는 항목만 수락됨으로 표시 | 발화자·관련 인물을 실행자로 임의 확정하지 않음 |
| PRD-T-03 | 산출물·완료 기준 유지 | 결과물과 확인 방법을 함께 조회 | 기한·담당이 없으면 미확인 항목으로 표시 |
| PRD-T-04 | 일정과 중복 조정 | 같은 의미의 접촉은 한 곳에만 존재 | 회의 준비·자료 전달 같은 독립 업무는 유지 |
| PRD-T-05 | 수정 범위·버전 보호 | 제목 정정은 해당 범위만 바꿈 | 오래된 버전의 저장을 감지하고 최신 결과 조회 안내 |
| PRD-T-06 | 완료와 후보 구분 | 실행 증거 또는 담당 확인이 완료에 연결 | AI의 완료 추정은 후보 상태 유지 |
| PRD-T-07 | 복구 가능한 저장 | 재시도해도 같은 업무가 중복 생성되지 않음 | 응답 유실과 실제 저장 실패를 구분해 조회·재시도 |

## 추적 관계

T02–T03 → PRD-T-01·04, T04–T05 → PRD-T-02·03, T06–T08 → PRD-T-04–07. 단계는 [SOP](tasks-sop.md), 인계는 [MoW](tasks-mow.md)를 함께 봅니다.

## 합성 수용 사례

- “내일까지 견적서를 보내 주세요”에서 수락 발화가 없으면 요청됨·수락 미확인입니다.
- 동일한 고객사 A 통화를 반복 언급해도 하나만 남깁니다. 고객사 B 통화는 별도로 유지합니다.
- 요약만 짧게 고치면 이미 확정한 할 일의 담당·기한·ID는 유지되어야 합니다.
- 기존 기록 조회 실패를 빈 목록으로 바꾸어 덮어쓰지 않습니다.

## 범위와 출처

IScribe의 할 일·일정 명세, writingAgent의 수정 계약에서 도출한 요구 초안입니다. 특정 제품의 현재 구현과 동일하다고 주장하지 않습니다. 예시는 합성이며 기업·인물·운영 식별자는 포함하지 않았습니다. 검증 표본·측정 기간·수용 임계값은 적용 조직에서 합의해야 합니다.
