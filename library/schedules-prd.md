# 일정 PRD — 시간을 지어내지 않는 일정 도구

상태: 제안 · 현업 검증 전. 제안하는 동작과 수용 조건이며 특정 제품의 구현 목록이 아닙니다.

| 요구 ID | 필요한 동작 | 수용 사례 | 경계·실패 |
|---|---|---|---|
| PRD-S-01 | 이벤트와 결과물 구분 | 고객 통화는 일정, 제안서 전달은 할 일 | 전달 마감 시간이 있어도 일정으로 승격하지 않음 |
| PRD-S-02 | 기준시각·시간대 기록 | 상대 날짜를 해석한 근거 조회 | 기준일이 없으면 원문과 미정 상태 유지 |
| PRD-S-03 | 확정 상태 분리 | 시간 제안과 상대 수락을 따로 표시 | 잠정 일정을 확정으로 출력하지 않음 |
| PRD-S-04 | 시간 불확실성 보존 | 날짜만 알면 시간 미정 | 전사 00:35를 00시 35분 약속으로 해석하지 않음 |
| PRD-S-05 | 의미 중복 제거 | 같은 대상·시점·목적의 통화는 한 건 | 날짜·대상이 다른 통화는 보존 |
| PRD-S-06 | 저장·변경 추적 | 등록 ID, 기준 버전, 변경 이유 유지 | 응답 유실·오래된 버전으로 덮어쓰기 방지 |
| PRD-S-07 | 독립 준비 업무 유지 | 미팅과 자료 준비를 각각 조회 | 일정 우선 규칙으로 준비 업무 삭제 금지 |

## 성공 기준을 정하는 방법

미정 날짜, 서로 다른 시간대, 자정 경계, 반복 일정, 취소 후 재조율, 제목이 같은 다른 고객 일정으로 수용 사례를 만듭니다. 기대 분류와 날짜 해석을 결과를 보기 전에 기록합니다. 누락·중복·잘못된 확정을 별도 집계하고 응답 오류도 실패에 포함합니다. 이 문서에서는 실행 결과나 합격률을 주장하지 않습니다.

## 연결과 근거

S01–S04 → PRD-S-01–04, S05–S07 → PRD-S-05–07. [SOP](schedules-sop.md)·[MoW](schedules-mow.md)를 함께 사용합니다. IScribe·writingAgent의 구분 명세와 정적 규칙에서 도출한 공개 초안입니다. 기업·인물은 가명으로 대체했으며 실제 원문·계정·연락처는 포함하지 않습니다.
