# 경험을 옮기는 틀 — “요약만 줄여 주세요”가 업무를 지우면 안 된다

## 근거의 성격

writingAgent의 정적 수정 계약에서 도출한 실패 방지 사례입니다. 아래 상황은 설명을 위한 합성 사례이며 실제 장애나 고객 인터뷰를 재현한 기록이 아닙니다.

## 상황과 수정 이유

노트에는 고객사 A에 대한 확정 업무 2건과 일정 1건이 있습니다. 담당자 A는 요약만 짧게 고쳐 달라고 요청했습니다. 수정 도구가 문서 전체를 새로 쓰면서 기존 업무를 빠뜨린다면, 표현 수정이 업무 데이터 손실로 번집니다.

## 가져갈 규칙

- 변경 요청이 겨냥한 영역을 먼저 표시합니다.
- 요약만 변경하는 요청은 다른 업무·일정의 식별자, 담당, 기한, 확정 상태를 유지합니다.
- 새 사실이 기존 내용과 충돌하면 영향을 받는 영역과 이유를 기록합니다.
- 기존 기록을 읽지 못한 상황을 빈 노트로 대체해 저장하지 않습니다.
- 생성한 수정 후보, 실제 저장 성공, 후속 시스템 반영을 각각 구분합니다.

## 확인 방법

수정 전후의 업무·일정 ID와 값을 비교합니다. 기준 버전이 오래됐거나 원본 조회가 실패한 사례도 검사합니다. 이 자료는 수용 조건을 제안할 뿐 실제 서비스의 모든 화면·저장 경로에서 통과했다고 주장하지 않습니다.

## 출처와 공개 범위

writingAgent의 `backend/prompts.py`와 노트 수정 계약을 문서·정적 코드로 확인했습니다. 내부 API 주소·인증 방식·계정·원문 데이터는 공개 자료에서 제외했습니다. 원본 코드 전체를 복제하지 않고 재사용할 판단 규칙만 정리했습니다.
