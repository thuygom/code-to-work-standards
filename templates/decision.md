# 변경 결정 카드

결과 책임자가 근거를 확인한 뒤 작성합니다. 평가·현업 확인 전에는 `미결정`으로 남겨 주세요. 승인 범위 밖의 업무·시스템에 자동 적용하지 않습니다.

| 항목 | 작성 내용 |
|---|---|
| 결정 ID | 예: `DEC-N-001` |
| 결정 상태 | 미결정 / 채택 / 일부 채택 / 보류 / 기각 |
| 결정일·결과 책임자 역할 |  |
| 검토·협의 역할 |  |
| 관련 변경안·실행·사례 | `CHG-`, `RUN-`, `CASE-` |
| 영향 단계·요구·지도 | 예: `N01`, `PRD-N-01` |
| 대체하는 이전 결정 | 없으면 없음 |
| 공개 검토 상태 | 미검토 / 가공 중 / 공개 승인 |

## 검토한 근거

- 문제와 비교한 대안:
- 실제 수행한 평가와 미수행 평가:
- 출력 유형별 고유 사례 수와 수용·보류·실패:
- 치명 오류·필수 조건·근거 품질:
- 사람의 수정 부담·시간·호출·비용:
- 보류 사례의 독립성 및 소표본 한계:

## 결정과 적용

- 결정 이유:
- 채택하는 업무·출력 유형·조건:
- 적용하지 않는 범위:
- 개정할 SOP·PRD·지도·평가 기준과 버전:
- 구현 완료 여부와 별도 구현 과제:
- 적용 담당자와 시점·조건:

## 남은 한계와 재검토

- 미확인 사항:
- 새 근거·고객 답변·제품 변경 등 재검토 조건:
- 되돌림 조건과 담당자:
- 다음 검증 사례·작업:

소표본의 통과를 전체 운영 성능으로 보장하지 않습니다. 문서 채택, 구현 완료, 운영 배포, 현업 수용은 서로 다른 상태로 기록합니다.
