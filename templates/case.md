# 평가 사례 카드

표현이 같은 정답 문장보다 기대 사실·판단 상태·완료 조건을 작성해 주세요. 평가 전에 기준을 고정하고, 실측하지 않은 값은 채우지 않습니다.

| 항목 | 작성 내용 |
|---|---|
| 사례 ID | 예: `CASE-N-001` |
| 제목 |  |
| 원천 유형 | 실제 / 합성 |
| 출력 유형 | N1 / N2 / B1 / B2 또는 등록된 새 업무 유형 |
| 사용 구분 | 개발 / 최종 보류 / 예시 전용 |
| 기대 결과 상태 | 초안 / 현업 승인 |
| 관련 관찰·단계·요구 | 예: `OBS-N-001`, `N01`, `PRD-N-01` |
| 사례 관리자·현업 검토자 역할 |  |
| 입력 버전·기준시각 |  |
| 분할·기준 고정일 |  |
| 공개 검토 상태 | 미검토 / 가공 중 / 공개 승인 |
| 비공개 원문 참조 | 식별자만 기재하고 실제 파일 링크·경로는 넣지 않습니다. |

## 요청과 입력

- 사용자가 하려는 일:
- 필요한 결과와 범위:
- 입력·참고 자료 목록:
- 공개 가능한 입력 또는 승인된 요약:
- 알려지지 않은 정보:

## 기대 사실과 근거

| 항목 ID | 필수 사실·결정·조건 | 상태 | 근거 ID·위치 | 필수 여부 |
|---|---|---|---|---|
| F01 |  | 제안 / 요청 / 수락 / 확정 / 미정 / 가설 |  |  |

## 수용 조건

- 정상 결과에서 확인할 것:
- 허용되는 표현 차이:
- 반드시 표시할 불확실성:
- 정당한 보류·실패 처리:
- 완료 확인 근거:
- 금지할 추론·잘못된 확정:
- 치명 오류:

## 검토와 분할 관리

- 검토자 간 이견과 조정 결과:
- 동일 회의·고객·원문의 파생 사례:
- 개발 과정에서 입력·기존 결과·기대 결과를 본 사람과 용도:
- 보류 유지 또는 개발용 전환 사유:
- 원문 가공으로 달라진 판단 조건:

합성 사례는 실제 성과 집계에서 제외합니다. 보류 정보를 개선에 사용했다면 개발용으로 전환하고 새 보류 사례를 확보해 주세요.

최종 보류 사례의 입력·기대 결과·기존 결과는 공개 승인을 받았더라도 평가 전에 게시하지 않습니다. 평가 후 공개한 사례도 다음 개선 주기의 새로운 독립 보류 사례로 재사용하지 않습니다.
