# 변경안 카드

변경 결과를 보기 전에 해결할 문제, 원인 가설, 비교 조건과 수용 기준을 작성해 주세요. 이 카드는 구현·배포 완료를 뜻하지 않습니다.

| 항목 | 작성 내용 |
|---|---|
| 변경 ID | 예: `CHG-N-001` |
| 상태 | 제안 / 비교 준비 / 비교 중 / 결정 대기 |
| 작성일·담당자 역할 |  |
| 출력 유형·적용 범위 | N1 / N2 / B1 / B2 및 제외 범위 |
| 관련 근거·관찰·실행 | `CODE-`, `OBS-`, `RUN-` |
| 영향 단계·요구 | 예: `N01`, `PRD-N-01` |
| 공개 검토 상태 | 미검토 / 가공 중 / 공개 승인 |

## 문제와 원인 가설

- 현업이 겪은 문제와 업무 영향:
- 관측 근거와 아직 추정인 부분:
- 원인 유형: 입력 / 업무 절차 / 규칙 / 맥락·근거 / 실행 / 평가 / 모델 수행
- 다른 가능한 원인:
- 이 가설을 지지하거나 반박할 결과:

## 제안 변경과 비교 계획

| 항목 | 작성 내용 |
|---|---|
| 현행 방식 |  |
| 바꾸는 1~2개 조건 |  |
| 유지하는 조건 | 입력·근거·모델·출력·권한·검토·완료 조건 |
| 개발 사례 |  |
| 최종 보류 관리 | 관리자·분할 시점·정보 비공개 방식 |
| 수행 방식 | 수동 재현 / 모의 실행 / 실제 시스템 실행 |
| 측정 지표·목표 | 기준선과 수용 기준을 먼저 기록합니다. |
| 치명 오류·중단 조건 |  |
| 필요한 구현·운영 승인 | 실제 변경 작업이 있을 때 별도로 기록합니다. |

## 예상 영향

- 사람의 역할·검토·인계 변화:
- 예외·반려·재개 경로 변화:
- 품질·시간·호출·비용의 예상 관계:
- 기존 동작에 영향을 줄 위험과 확인 방법:
- 적용을 되돌릴 조건:

비교 결과와 채택 판단은 [실행 기록](evaluation-run.md), [결정 카드](decision.md)에 남깁니다. 결과가 좋았다는 이유로 사후에 평가 기준이나 비교 대상을 바꾸지 않습니다.
